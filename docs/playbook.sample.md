# Playbook サンプル: 未カバー関数へのユニットテスト追加

> Devinの Playbook 画面に貼り付けて使う想定。セッション起動時に対象関数名だけ渡せば動くようにしてある。

## 概要
指定された関数に対してユニットテストを追加し、テストとLintがグリーンな状態でPRを作成する。

## 入力
- 対象: `{{ 対象のモジュール.関数名 }}`（例: `taskman.service.TaskService.delete`）

## 手順
1. 対象関数の実装を読み、分岐（正常系・異常系・境界値）を洗い出す
2. `tests/` の既存テストのスタイルと `service` フィクスチャを確認する
3. 洗い出した分岐を網羅するテストを追加する。1テスト1アサーションの意図が明確になるよう命名する
4. `pytest -q` を実行し全件パスすることを確認する
5. `ruff check .` を実行しクリーンであることを確認する
6. PRを作成する。説明に「追加したテストケースの一覧」と「実行したコマンド」を書く

## 完了条件
- 新規テストが追加されている
- `pytest -q` が全件パス
- `ruff check .` がクリーン
- PRが作成されている

## 禁止事項
- `src/` 配下（プロダクションコード）の変更（バグを見つけた場合は修正せず、PR説明に報告するだけにする）
- 依存パッケージの追加
- 既存テストの削除・書き換え
